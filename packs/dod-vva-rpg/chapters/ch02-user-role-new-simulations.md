# Chapter 2: User's Role in VV&A of New Simulations

## Core Idea
The User owns the problem the M&S must serve: clear intended use, acceptance-oriented requirements, domain truth for validation, and ultimate need for a credible accreditation decision.

## Frameworks Introduced
- **User-driven requirements**: mission/decision objectives → M&S requirements → measures and acceptability thresholds.
- **Engagement lifecycle**: concept → development milestones → acceptance/accreditation support → operational use feedback.
- **SME channel**: Users supply or broker subject-matter expertise for face validation and referent judgment.

## Key Concepts
- **Intended use statement**: who uses the M&S, for what decisions, under what conditions, with what stakes.
- **Acceptability criteria**: what “good enough” means before resources are spent on V&V.
- **Data expectations**: required input/output data characteristics and constraints the User can actually supply.
- **Participation in reviews**: requirements reviews, conceptual model review, validation events, accreditation package review.
- **Operational feedback**: after fielding, Users report mismatches that trigger re-V&V or re-accreditation.

## Mental Models
- **Problem owner ≠ builder**: Users must not outsource intended-use clarity to developers.
- **Thresholds before techniques**: agree pass/fail or tolerance bands before running validation cases.
- **Use drives independence**: higher User reliance on results → stronger demand for independent V&V Agent work.

## Anti-patterns
- “Build something useful” without a written intended use.
- Changing the decision context midstream without reopening accreditation criteria.
- Withholding operational data that validation depends on.
- Signing accreditation recommendations without reading residual-risk statements.

## Key Takeaways
1. Users define intended use and acceptability; everything else traces to that.
2. Early and sustained User engagement beats end-loaded acceptance fights.
3. SMEs and operational data are User-side validation assets.
4. Post-use feedback is part of the VV&A lifecycle, not optional commentary.
