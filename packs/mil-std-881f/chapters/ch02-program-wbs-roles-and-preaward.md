# Chapter 2: Program WBS, Roles, and Pre-Award Construction

## Core Idea
Section 2 directs Government program management: build a Program WBS that frames the entire defense materiel item before award, document it, and push the right levels into solicitations so offerors extend a coherent Contract WBS rather than inventing incompatible trees.

## Frameworks Introduced
- **Program WBS attributes** — complete coverage of the PE/materiel item, product orientation, stable upper levels, extendable lower levels.
- **Preparing a Program WBS** — develop/document, select elements from the right commodity appendix, set levels, write the dictionary, avoid known pitfalls and exclusions.
- **Solicitation linkage** — RFP/SOW and CDRL/DID expectations so contractor management control systems, logistics, and PPBE interfaces align to the Program WBS.
- **Roles** — PM owns Program WBS integrity; contractors own Contract WBS extension under Government approval; supporting Government entities (depots, labs, FFRDCs, test sites) use the same contract/agreement language.

## Key Concepts
- **Element selection** — start from the commodity appendix (A–J) that matches the materiel item; add Common Elements where they apply.
- **Level setting** — go deep on high-cost, high-risk, high-technical, or special-interest items; keep upper levels comparable across similar programs for historic data.
- **Dictionary content** — name, definition, what is included/excluded, and interfaces to adjacent elements.
- **Exclusions pitfall** — do not omit effort that belongs under a product element just because it is performed by a different org or contract.
- **RFP artifacts** — require WBS-aligned IMS/IMP thinking, CSDR/cost reporting alignment where applicable, and proposal WBS that maps to the Program WBS.
- **Agreements beyond industry contracts** — MOAs, MIPRs, and intra-Government work still use Contract WBS discipline.

## Mental Models
- **Upper levels stable, lower levels flexible** — protect cross-program comparability while allowing contractor detail.
- **Dictionary is the contract of meaning** — if two teams disagree what 'Fire Control' includes, the dictionary is the authority.
- **Solicit the structure you can manage** — if you cannot report or oversight it, do not pretend the RFP WBS goes there.

## Anti-patterns
- Issuing an RFP with only a Level-1 title and hoping offerors converge.
- Mixing multiple commodity appendices' top structures without a documented hybrid rationale.
- Letting cost-report templates dictate WBS parents instead of product logic.
- Forgetting Government-performed slices of the Program WBS.

## Key Takeaways
1. Government builds and owns the Program WBS pre-award.
2. Commodity appendix + Common Elements + dictionary is the construction recipe.
3. RFP/CDRL language must demand Contract WBS extension of the Program WBS.
4. Intra-Government agreements follow the same WBS rules as industry contracts.
