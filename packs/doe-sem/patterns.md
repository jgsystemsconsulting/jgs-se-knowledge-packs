# Patterns — DOE SEM Version 3

## 1. Plans Triad Before Build
- **When:** Project kickoff under SEM.
- **How:** Baseline Project Plan, QA Plan, and CM Plan in Planning; refuse Construction entry without them.
- **Trade-offs:** Up-front ceremony vs uncontrolled mid-project thrash.

## 2. Three-Gate Stage Rhythm
- **When:** Every development stage.
- **How:** Schedule Structured Walkthroughs on major work products, at least one In-Stage Assessment, and a formal Stage Exit with owner decision.
- **Trade-offs:** Calendar time vs late discovery of defects and unauthorized scope creep.

## 3. Size-Tailored Artifact Set
- **When:** Small vs large IT investments.
- **How:** Use SEM size exhibits to scale documents; never scale away baselining, CM, or exits.
- **Trade-offs:** Judgment required vs one-size bureaucracy or chaos.

## 4. RTM as Living Spine
- **When:** Requirements start.
- **How:** Create RTM early; update each stage; drive test design from it; review coverage at exits.
- **Trade-offs:** Maintenance cost vs undetected scope holes at acceptance.

## 5. Feasibility Kill-Point
- **When:** Planning identifies weak business/technical case.
- **How:** Explicit feasibility review with abandon as a valid Stage Exit outcome.
- **Trade-offs:** Political difficulty vs funding failing concepts into design.

## 6. Functional then Physical Design
- **When:** Solution shape still unstable.
- **How:** Freeze functional design before system design/platform lock-in; change via CM.
- **Trade-offs:** Two design passes vs premature COTS/platform commitment.

## 7. Construction Includes Unit Proof
- **When:** Build stage.
- **How:** Require unit verification and peer review evidence in Construction exit package.
- **Trade-offs:** Slightly slower coding vs integration test pile-ups.

## 8. Acceptance ≠ Test Pass
- **When:** Installation stage.
- **How:** Separate technical test evidence from owner acceptance decision criteria and training completion.
- **Trade-offs:** Extra governance vs operational rejection after “green” tests.

## 9. Maintenance Mini-SEM
- **When:** Production changes.
- **How:** Run nested identify→analyze→design→build→test→accept→deliver proportional to change risk.
- **Trade-offs:** Process overhead on tiny fixes vs silent baseline erosion.

## 10. Modernize Mechanisms, Keep Intents
- **When:** Applying 2002 SEM in agile/cloud shops.
- **How:** Map sprints to stage intents; keep exits, CM baselines, RTM, and independent assessment roles.
- **Trade-offs:** Translation work vs either fossilized waterfall or uncontrolled continuous deploy.
