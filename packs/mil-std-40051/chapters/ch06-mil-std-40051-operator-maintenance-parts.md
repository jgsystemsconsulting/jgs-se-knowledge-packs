# Chapter: Operator, maintenance, parts, and supporting information

## Core Idea

Appendices B through G specialize the common method for the main equipment-publication families: general information and equipment description, operator instructions, troubleshooting, maintenance instructions, parts information, and supporting information. Rules cover both page-based and IETM presentations. This pack names the duties of each family. It does not copy exemplar plates or sample work packages.

## Frameworks Introduced

### Appendix map for the core TM set

| Appendix | Family |
| --- | --- |
| B | General information, equipment description, and theory-style front content for the end item |
| C | Operator instructions |
| D | Troubleshooting procedures |
| E | Maintenance instructions |
| F | Parts information (including RPSTL-oriented content) |
| G | Supporting information |

### Shared authoring pattern

1. Confirm the matrix selected the family.
2. Apply section 4 structure (modules, WPs, IDs) and section 5 detailed controls.
3. Fill only the content objects that appendix requires for the chosen maintenance level and output.
4. Keep warnings, cautions, and notes inside the safety rules from the general spine.
5. Do not borrow layout from a sample figure when the structured requirement already states the content duty.

### Output-neutral content, output-aware rendering

The same technical objects can render as linear pages or interactive nodes. Troubleshooting trees, maintenance tasks, and parts lists must remain traceable to WP identifiers in either output.

## Key Concepts

- **Operator family.** Tasking the user who operates the equipment, including setup and operating instructions selected by the matrix.
- **Troubleshooting family.** Fault isolation and related diagnostic content with procedure structure the standard requires.
- **Maintenance family.** Remove/install, adjust, repair, and related maintenance tasks through the levels the matrix opened.
- **Parts family.** Parts information and RPSTL-oriented presentation so supply and maintenance share one parts truth.
- **Supporting information.** Ancillary data the TM needs but that is not itself a procedure (tables, references, and similar support objects as the appendix defines).
- **General information / equipment description.** Context the user needs before tasks: description, location, and related overview content.

## Mental Models

- **Family first, page second.** Choose the appendix family from the matrix before debating pagination.
- **RPSTL is parts truth, not decoration.** Parts information must stay consistent with maintenance task references.
- **No plate worship.** Sample pages teach shape; they are not source text for this pack.

## Key Takeaways

- Appendices B-G are the core operator-through-parts set.
- Both page-based and IETM outputs are in scope for these families.
- Work-package structure still governs task content.
- Matrices decide inclusion; appendices decide family rules.
- Exemplar plates and sample images are not reproduced here.
