# Chapter 2: TM Structure, Chapters, and Work Packages

## Core Idea
Page-based manuals are assembled from titled divisions—volumes, chapters, and especially **work packages**—with consistent numbering so operators and maintainers can navigate, cite, and update material without breaking the book.

## Frameworks Introduced
- **Manual styles and trim sizes** — standard style/size table drives layout envelopes for the selected manual class.
- **Chapters as divisions** — chapters partition operator vs maintainer content and major functional areas.
- **Work package anatomy** — title, initial setup, procedural steps, follow-on maintenance, references, and end-of-WP statements as applicable.
- **WP numbering** — stable identifiers; renumbering rules matter when inserting change packages.
- **Multi-volume and combined manuals** — volume splits and multi-level combined manuals follow explicit assembly rules.
- **RPSTL and supporting WPs** — repair parts/special tools lists and supporting information integrate as structured WPs, not ad-hoc annex dumps.

## Key Concepts
- **Initial setup information** — tools, parts, references, personnel, and equipment conditions required before task start.
- **Task/procedure steps** — numbered procedural hierarchy suitable for the maintenance level; fourth-level subordinate steps when needed.
- **End of task / end of work package** — explicit closure statements so users know completion criteria.
- **References** — internal WP/figure/table references and external TM references with prescribed formats.
- **Tables and figures** — numbering, titles, continuation headers, and placement rules relative to procedures.
- **Selective application** — not every WP type appears in every manual; content selection matrix drives inclusion.

## Mental Models
- **WP = reusable training/ops module** — design once, cite many, change with traceability.
- **Navigation is a safety property** — broken numbering and missing setup data cause wrong-task execution.
- **Structure before prose** — outline WPs to the matrix, then write steps.

## Anti-patterns
- Narrative chapters without WP boundaries on a WP-contracted TM.
- Skipping initial setup because 'technicians know'.
- Renumbering WPs casually across changes without change-package rules.
- Figures without numbers/titles referenced from steps.

## Key Takeaways
1. Chapters + work packages are the structural backbone of page-based TMs.
2. Initial setup and closure statements are normative task framing.
3. Numbering stability enables citation and change control.
4. Matrices decide which WP types appear.
