# Chapter 6: Change Packages and Revision Marking

## Core Idea
TMs live under continuous revision. The standard specifies how changes are packaged, how revision bars and change metadata appear, and how page/WP renumbering works so field libraries and training fleets can trust effectivity.

## Frameworks Introduced
- **Change package concept** — collected changed pages/WPs with change instructions, not silent file swaps.
- **Vertical revision bars** — mark technical changes; editorial-only fixes may be exempt per rules; figures/tables have specific bar placement conventions.
- **Page count thresholds** — rules for when a change vs a revision is appropriate based on extent of change (including bound publication practices).
- **Renumbering WPs and pages** — insertion algorithms (e.g., avoid collisions when adding WPs) and knock-on TOC/title updates.
- **Title-page change history** — dates of issue for original and each change keep the manual's amendment state visible.
- **Supersession statements** — prior TM identity and disposition.

## Key Concepts
- **Technical vs editorial change** — technical changes get bars; pure grammar/spelling may not; still control the file.
- **Figure/table change marking** — bars left/right of titles depending on whether number/title vs content changed.
- **Multi-volume change control** — change only affected volumes but keep identity aligned.
- **Training fleet updates** — changed TMs must reach schools and units with the same package discipline as operational libraries.
- **DMWR/NMWR changes** — depot/national docs follow the same change logic with their title specialties.
- **Configuration link** — TM changes track equipment configuration/effectivity lists.

## Mental Models
- **Effectivity is a user safety property** — wrong change state → wrong torque, wire, or software step.
- **Bars are for humans; metadata is for libraries** — both required.
- **Prefer traceable packages over silent PDFs** — auditors and trainers need change lineage.

## Anti-patterns
- Replacing the whole PDF with no change instructions or bars.
- Renumbering half the manual without TOC/title updates.
- Marking every cosmetic edit with bars until bars lose meaning.
- Training organizations on a different change state than the field.

## Key Takeaways
1. Changes are packaged, marked, and effectivity-tracked.
2. Revision bars and title-page dates are mandatory signals.
3. WP/page insertion follows collision-avoiding renumber rules.
4. Training and ops fleets must share change state.
