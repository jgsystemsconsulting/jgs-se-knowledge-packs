# Chapter: Content selection method

## Core Idea

Appendix A holds the technical manual requirements with content selection matrices. The materiel developer and acquiring activity use those matrices to decide which content objects a given TM type and maintenance level must carry. This pack explains the method. It does not reproduce matrix cells, checkboxes, or sample filled sheets.

## Frameworks Introduced

### Matrix as the tailoring instrument

Section 4 points selective application and tailoring to Appendix A. Section 6 acquisition guidance tells the contract to cite a filled-out content selection matrix. The matrix is therefore both a technical control and an acquisition artifact.

### What a row decides

At a high level, each matrix decision answers:

1. Which TM type is being built (operator, maintenance, parts, supporting information, special product, and so on).
2. Which maintenance level or product class the row addresses.
3. Whether a content object is required, selectable, or not applicable for that intersection.
4. Whether IETM functionality or page-based presentation changes the object's shape without changing its technical duty.

### Relationship to IETM functionality blocks

Appendix A also carries IETM functionality general and detailed requirements and functionality definitions (access, annotation, and related behaviors). Those blocks travel with the matrix method so interactive delivery does not invent a second content model.

## Key Concepts

- **MATDEV responsibility.** Tailoring is not author freelancing. The developer records choices in the matrix the contract recognizes.
- **Service limits still apply.** Prefixed requirements remain bounded even after a matrix include.
- **Acquisition citation.** Title, number, and date of the standard plus the filled matrix are the usual acquisition pair.
- **No cell copy here.** Synthesized notes describe how to use the method. They never paste row text or graphic matrix layouts from the PDF.

## Mental Models

- **Select, then author.** Empty matrix decisions produce empty or noncompliant manuals.
- **One method, many products.** Operator books and depot products share the selection instrument and diverge only where the matrix says so.
- **Functionality is content-adjacent.** IETM behaviors are specified next to content selection so navigation features stay traceable.

## Key Takeaways

- Appendix A is the content-selection and IETM-functionality home.
- Contracts should cite the filled matrix with the standard.
- This pack never reproduces matrix cells or plate images.
- Downstream chapters assume a matrix decision already exists.
- Tailoring language in section 4 is executed here, not in the margins.
