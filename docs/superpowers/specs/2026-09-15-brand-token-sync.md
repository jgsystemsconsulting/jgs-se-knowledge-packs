# Brand token sync (P13)

Date: 2026-09-15
Status: approved for planning
Package: P13, brand-token-sync

## Problem

The `:root` brand token block and the four `@font-face` rules are hand-duplicated between
`docs/index.html` and the HTML template inside `tooling/gen_packs_page.py`. `docs/packs.html` is
generated output (RR-B-00: do not hand-edit), so its copy of the tokens is only as fresh as the
last regeneration. Nothing compares the two copies, and the CI-covered self-containment scan
(`[html-assets]`) checks for external assets, not token parity. Any visual retune of the dark
drafting brand that edits one copy and forgets the other ships two subtly different pages.

## Codebase context

- `docs/index.html:32-41`: the live `:root` block (ink scale, line, mute, text, paper, mono/sans
  stacks, two pad clamps). Lines 25-30 hold the four self-hosted `@font-face` rules above it.
- `tooling/gen_packs_page.py:93-106`: the same four `@font-face` rules and the same `:root` block,
  hardcoded inside the `render()` f-string template (braces doubled for formatting).
- `docs/packs.html`: generated by `gen_packs_page.py` from `SKILLS.md` and `RELEASE-INFO.txt`.
- `tooling/check_release.py`: `[rr-b-30]` verifies packs.html freshness (local-only, pre-tag);
  `[html-assets]` (P12) scans every `docs/*.html` for external assets and is CI-covered. Its scan
  logic is mirrored as an inline heredoc in `.github/workflows/validate.yml` under the pinned step
  name "HTML self-containment", and `tooling/test_ci_gate.py` pins the pattern text byte-for-byte
  in both files (`HTML_ASSET_PAIR`).
- `docs/fonts/` already holds the four woff2 files both pages reference. No CDN anywhere.
- `var(--ink-4)` appears in zero CSS rules on either page. The token is defined three times and
  used never.

## Taste direction

This is a refinement brief, not a design system. The brand is a dark drafting document: near-black
ink grounds in four steps, hairline rules between sections, monospace headings and uppercase
wide-tracked labels, warm paper as the only accent (primary CTA, focus ring, hover underline), and
the grid-lined drafting sheet in the footer. JetBrains Mono for anything that reads like a
document ID, Inter for prose. No third-party assets; fonts stay self-hosted in `docs/fonts/`.

Rules for future token work, which this package makes enforceable:

1. `docs/index.html` is the single source of truth for brand tokens. Edit there first.
2. Token changes ride the existing generator: edit, run `gen_packs_page.py`, commit both.
3. No new colors, no new font families, no CDN. If a change needs either, it is a new package.
4. The only value change in this package is deletion: remove the dead `--ink-4` token.

## Approach

Chosen: index.html owns the tokens; the generator extracts them at render time; the CI-covered
html-assets scan asserts the generated page still carries the exact block. One source, no new
check script, parity enforced where CI already looks.

Rejected alternatives:

- Python constant in `gen_packs_page.py` with a compare assert: keeps two copies to edit and adds
  a new assert to maintain. The constant is still a second source of truth.
- Shared `docs/brand.css` linked by both pages: breaks the stated self-containment convention
  ("inline CSS, no third-party asset", enforced by `[html-assets]`), costs a second request per
  page, and needs the convention relaxed for a two-page site. Not worth it.

## Design

### 1. Marker block in docs/index.html

Wrap the four `@font-face` rules and the `:root` block in explicit comments:

```
/* BRAND-TOKENS:BEGIN (single source; tooling/gen_packs_page.py copies this verbatim) */
... @font-face x4 ...
:root{ ... }
/* BRAND-TOKENS:END */
```

**Slice rule:** the contract is the exclusive interior between the BEGIN line and the END line
(neither marker comment line is part of the slice). Exactly one BEGIN and one END must appear,
with BEGIN before END. Unbalanced, missing, reversed, or duplicate markers are errors. The
font-comment lines above the BEGIN marker (e.g. the "Self-hosted brand fonts..." note) stay
outside the contract. Everything inside the exclusive slice, byte for byte, is the brand
contract. The dead `--ink-4` token is deleted from the block in the same edit.

### 2. Generator extraction (tooling/gen_packs_page.py)

Delete the hardcoded `@font-face` and `:root` lines from the template. Add a small
`brand_tokens()` function that reads `docs/index.html` relative to the repo root (same root
resolution pattern `gen_packs_page.py` already uses for other paths), slices the exclusive
interior per section 1, and **raises a plain Exception** (never `sys.exit`) if markers are
missing, duplicated, reversed, or unbalanced. The CLI `__main__` path catches that exception,
prints a clear stderr message, and exits nonzero. Callers that import `brand_tokens` /
`render` (including `check_release.py` rr-b-30) must see a normal exception, not `SystemExit`.
`render()` splices the extracted text into the template through a literal placeholder (for
example `__BRAND_TOKENS__` inside the f-string, replaced after formatting) so the single-brace
CSS never has to be re-escaped for the f-string.

### 3. Parity lock in CI

Extend the existing `[html-assets]` check in `tooling/check_release.py` with one assertion:
extract the brand block from `docs/index.html` with the same exclusive-slice algorithm as
section 2 (inline the algorithm in the gate and in the CI heredoc; do not import
`gen_packs_page.brand_tokens` from CI, which never executes checkout Python). Require the
extracted block to appear verbatim as a substring of `docs/packs.html`. Failure message names
the fix: rerun `tooling/gen_packs_page.py`. Tag the failure `[brand-tokens]`.

This check lives in a mirrored surface, so the change is a three-file touch by repo convention:

1. `tooling/check_release.py`: the assertion (inline extract).
2. `.github/workflows/validate.yml`, heredoc under "HTML self-containment": the same lines.
3. `tooling/test_ci_gate.py`: add the `BRAND-TOKENS` marker literals (`BEGIN` and `END` strings)
   to `HTML_ASSET_PAIR` so byte parity between the two surfaces stays pinned; update the
   `html-clean-ok` positive fixture so it includes a minimal marker block and a packs.html that
   carries the same exclusive slice (otherwise the new assertion fails a clean fixture). Keep
   negative demo behavior intact.

The block is exact text, so the assertion is a substring test. No CSS parsing. Pin covers marker
literals and the exclusive-slice bounds comments if present as code comments in both surfaces;
extraction logic is duplicated by convention, same as the rest of the html-assets twin.

### 4. Dual-touch rule for shared chrome

The masthead and footer markup stay hand-mirrored between `index.html` and the generator template;
the DOC-ID and REV fields legitimately differ between the pages. Add a one-line comment above the
mast block in both sources noting the mirror, so the next editor knows the tokens are locked but
the chrome is not. Release REV updates keep flowing through the existing release flow; nothing in
this package changes it.

### 5. Token polish

Delete `--ink-4` only. Verified unused: `var(--ink-4)` matches zero rules in `docs/index.html`,
`docs/packs.html`, and the generator template. Everything else in the block ships unchanged.

## Verification

1. `python tooling/gen_packs_page.py` succeeds; `git diff docs/packs.html` shows only the brand
   block swap (font-face plus `:root` replaced by the extracted text, `--ink-4` gone).
2. `python tooling/check_release.py` passes on the clean tree.
3. Negative demo: edit one hex value in the exclusive brand slice of `docs/packs.html` by hand,
   rerun `check_release.py`, confirm the `[brand-tokens]` failure; restore. Deleting markers from
   `index.html` must make `brand_tokens()` raise (caught by CLI as nonzero exit) and must make
   the gate's inline extract fail with `[brand-tokens]` without `SystemExit` killing the process
   mid-check. Unbalanced markers (BEGIN without END) must fail the same way, not splice the rest
   of the file.
4. `python tooling/test_ci_gate.py` passes with the extended pair pin and the updated html-clean-ok
   fixture that carries markers + matching packs.html slice.
5. `grep -rn "ink-4" docs/index.html docs/packs.html tooling/gen_packs_page.py` returns nothing.
6. Both pages render identically to before (the block was byte-identical apart from the removed
   dead token), confirmed by opening `docs/index.html` and `docs/packs.html` locally.
